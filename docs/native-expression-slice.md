# Native expression slice — additive implementation, not a default-engine switch

After proposal #1 was merged and the owner asked to continue without requiring a PR, this change starts the bounded native implementation. The TypeScript engine remains the full-language reference and the existing `cannon` command is unchanged. No record/rule/transition, business policy, accepted expectation, stable ID, or default runtime is migrated silently.

## What runs without Node

`crates/cannon-core` is a standard-library-only Rust library with a `cannon-native` binary. Its current scope is **standalone pure expressions**: safe integers, Bool, JSON strings, arithmetic/comparison/equality, Boolean short-circuiting, and `if/then/else`. The native parser checks both branches before execution and records only operations actually executed. Unsupported names/full-language syntax are errors, not a request to fall back to JavaScript.

```sh
cargo test --workspace --locked --offline
cargo run --locked --offline --bin cannon-native -- eval '8 + 2 <= 10' --json
cargo run --locked --offline --bin cannon-native -- demo
cargo build --release --locked --offline
./target/release/cannon-native eval 'if 8 + 2 <= 10 then 0 else 3000'
```

Cargo requires an installed Rust toolchain. The repository pins 1.85.1; offline commands do not install that toolchain. There are no registry packages or Node subprocesses in the native build/runtime. Windows uses `cannon-native.exe`.

## Boundaries deliberately preserved

The accepted integer domain remains `[-9007199254740991, 9007199254740991]`, not the wider `i64` domain. Literal overflow is a parse error; arithmetic overflow is `INTEGER_RANGE`. There is no floating point, implicit conversion, division, or string concatenation.

String values are UTF-16 code-unit vectors. That choice preserves escaped lone surrogates accepted by the reference JSON string domain; using Rust `String` for language values would narrow that domain. Input source itself must be valid UTF-8. Source offsets and columns are UTF-16, lines and columns are one-based, and only LF increments the line, matching the existing source-location contract. No Unicode normalization is applied.

Compiled expressions are opaque, typed flat arenas. Clients cannot insert cyclic or unchecked AST nodes. Parsing has separate source, token, syntactic nesting and tree-depth limits; flat storage avoids recursively dropping an oversized rejected tree. Execution independently checks step, depth and trace budgets. A partial trace after an error never counts as a successful run. These are development safeguards, not a hostile-code sandbox or a wall-clock isolation claim.

## Native report protocol

`eval ... --json` emits one JSON document with schema `cannon.native.expression/1`: engine identity, exact source text and URI, limits, compilation/execution phase, result or structured error, executed step count, and ordered trace entries. Spans are relative to the single exact source embedded in that document. A skipped branch has no invented result. Transport/argument errors go to stderr and exit 2; they are not protocol responses. Exit codes are 0 for evaluation success, 1 for execution failure, and 2 for invalid source or invocation.

This report is **not** the full engine's snapshot/evidence/proposal format. It has no authenticated build identity or evidence freshness check and must not be used as an approval certificate. A matching value does not validate old TypeScript evidence against Rust. Versioned full-project provenance, historical replay, proposal identity and stale-base checks still belong to the reference engine until ported and separately verified.

## Independent conformance and differential checks

`conformance/expressions.tsv` contains 60 reviewed, language-neutral expectations. Columns: unique case ID, return type, JSON-encoded source, outcome category, JSON-encoded expected value/error code, and execution-limit overrides. Expected values are not generated by either evaluator. The native integration/unit suite independently exercises boundaries and malformed invocations.

```sh
npm ci --ignore-scripts
npm test
cargo build --workspace --locked --offline
node scripts/check-native-conformance.mjs
```

The runner wraps each expression in an unchanged reference rule and evaluates its body directly. It first checks independent expected answers in each engine, then compares every executed trace entry, step count and UTF-16 source span after explicitly removing the reference wrapper prefix. JSON wire normalization turns JavaScript `-0` into `0`; no execution steps or values are otherwise dropped. Compile-error cases compare error-code membership, not diagnostic wording or order; multi-error diagnostic parity is not claimed. The corpus does not prove all-input equivalence.

The new workflow runs on Linux, Windows and macOS. Existing Node 22/24 CI is not replaced. Record actual results from the workflow for the exact commit; workflow source presence is not evidence of success. Local development here verified 76 unchanged core tests and the 60 reference-side fixtures using preinstalled TypeScript 5.8.3 / Node types 25.1.0, not a fresh locked install. Rust compilation was not available locally and must be established by CI, not inferred from the TypeScript checks.

## Next bounded steps

Port stable-ID-aware nominal records and callable evaluation against independent fixtures, then full-source parsing/binding/checking. Follow with historical expectation replay and proposal/evidence identity. Only after those checks and native distribution tests should one default engine be selected. Full `.intent` files, LSP, persistent storage, AI-provider integration, performance claims and restoration of previously blocked editor files are not part of this change.
